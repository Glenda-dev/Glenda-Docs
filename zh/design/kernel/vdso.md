# Glenda vDSO 机制设计

## 1. 核心思想与背景

为减少频繁发起 IPC 的开销，Glenda 引入了 **vDSO (Virtual Dynamic Shared Object)** 机制。该机制允许内核（或服务）提供预定义的函数入口，使应用程序可以直接在用户态完成高频次的简单调用（如时间查询、简单的状态查询）。

## 2. 设计原理

vDSO 本质上是一种**非对称读写权限的共享内存映射**，并结合**用户态库代码 (vDSO Library)**：

- **内核/服务 (生产者)**：将页表映射为 **读/写 (RW)** 权限。
- **应用 (消费者)**：将该页映射为 **只读 (RO)** 权限。该页包含：
  - **动态链接的代码段**（函数实现）。
  - **同步的状态数据段**。

### 2.1 同步机制 (SeqLock)

在微内核中，无法在 vDSO 内部阻塞应用。为保证数据一致性（如内核更新 64 位纳秒计数器时，应用刚好在读取），采用 **顺序锁 (SeqLock)**：

1. **生产者 (内核/服务)**：
   - 增加序列号（变为奇数）。
   - 写入数据。
   - 增加序列号（变为偶数）。
2. **消费者 (应用)**：
   - 读取序列号。
   - 读取数据。
   - 再次读取序列号。
   - 若序列号发生变化或为奇数，则重试。

## 3. 分层式 vDSO 架构

### 3.1 内核级 vDSO (`kernel-vdso`)
- **功能**：由内核在创建 `VSpace` 时自动注入。
- **用途**：`clock_gettime`, `getcpu`, `gettimeofday`。
- **实现**：利用 hardware timer 寄存器或内核直接更新的时间窗口数据。

### 3.2 服务级 vDSO (`service-vdso`)
- **扩展性**：Glenda 支持用户态服务向其客户端注入 vDSO。
- **例子**：
  - **March (Time Server)**：提供更精细的时间管理。
  - **Prism (Terminal Server)**：向应用同步光标位置或视口尺寸变化。
  - **Nexus (FS Router)**：为常用的文件描述符映射索引，减少一次 Cap 寻址。

## 4. 与 Capability 系统的集成

在 Glenda 中，vDSO 注入通过 **Cap_Map** 实现：
- 服务在建立连接时，将一个具有只读权限的 `Frame` Capability 映射到客户端地址空间的固定位置（如 `VDSO_VA`）。
- 服务级 vDSO 指针在 `libglenda-rs` 中初始化，并根据 Capability 传递情况决定是否激活。
